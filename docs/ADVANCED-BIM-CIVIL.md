# BIM, survey and civil exchange workbench

The source implementation adds an authenticated exchange workbench with three workflows. Import an IFC STEP file and inspect supported geometry/metadata; apply literal IDS information requirements and export source-preserving IFC, OBJ and geometry-scene JSON. Import surveyed CSV, LAS or a supported GeoTIFF DEM, explicitly identify its CRS, reproject and construct a constrained surface. Author a civil alignment JSON and export analytic stations, cross sections and sampled earthwork quantities. All operations run only when a user invokes the workbench; this development pass did not run the application or any code.

## IFC geometry and round trip

`client/src/lib/ifcGeometry.ts` scans STEP statements while respecting strings/comments, parses nested aggregates and typed values, resolves local placement chains, reads project length units and retains the complete original STEP text. Supported SI prefixes and a conversion-based length factor into unprefixed metres are applied to mesh coordinates. Both IFC2X3 and IFC4-family header identifiers are admitted; this is a geometry subset, not a complete schema implementation.

Supported geometry consists of `IfcExtrudedAreaSolid` with rectangle/circle/simple closed-polyline profiles and positive local-Z extrusion, `IfcTriangulatedFaceSet` including `PnIndex`, and `IfcFacetedBrep`/shell surface models with simple planar polygon bounds. Circles have 48 segments. Concave simple polygon faces use ear clipping with bounded self-intersection checks. Nested `IfcLocalPlacement`, 2D/3D axis placements and geometric representation context/subcontext world coordinates are resolved. IFC axes remain Z-up for OBJ; geometry-scene exports use `x=X, y=Z, z=-Y` for the Y-up rendering/clash workbench.

The product metadata registry covers common building, spatial, opening and MEP classes plus products with a conventional `IfcProductDefinitionShape`. Direct `IfcRelDefinesByProperties` single-value property sets and stable source GlobalIds are retained. Type inheritance, quantities, aggregate properties, materials/classification, `IfcMapConversion`, mapped items, Boolean clipping, openings subtraction, hollow profiles, curved BRep surfaces and faces with holes are unsupported. Unsupported geometry is reported on the owning product; a failure can exclude that product's complete mesh. Root information is not invented for missing/invalid GlobalIds.

An unedited IFC export is the original text. Renaming replaces only the source product's Name argument; all other source records, identifiers, numerical spelling, properties and unsupported geometry remain intact. STEP X2/X4 Unicode strings are decoded; exported names escape quotes/backslashes and use X2 escapes for non-ASCII UTF-16 characters. Legacy ISO-8859 code-page escapes are retained as text. This supports name/metadata review and preservation, without claiming Revit/Archicad parametric editability or certified geometry round trips.

Limits: 20 MB source text; 100,000 entities; one million globally parsed STEP values; aggregate depth 32; placement/geometry reference depth 64; 200,000 geometry traversal steps; 10,000 products; 250,000 converted vertices; 500,000 converted triangles; 4096 vertices per simple polygon. Geometry-scene export has the separate 400,000-triangle limit required by the geometry workbench. Imported coordinates are finite and bounded to ±100,000 km.

## IDS requirements subset

`client/src/lib/bimValidation.ts` reads the buildingSMART IDS XML namespace with DTD/entity declarations prohibited. It implements exact literal entity class matching; literal `GlobalId`, `Name`, `Description` and `ObjectType` attributes; and direct untyped single-value property-set/name/value facets. Required, optional and prohibited attribute/property cardinalities are evaluated with explicit applicability occurrence bounds, and IFC version matching is checked. Entity requirements are always required. No entity subtype inheritance is inferred.

Unknown/foreign XML facet structure, duplicate fields, empty facet groups, unsupported restrictions, typed property checks, predefined-type entity facets, classification/material/parts facets and checks outside the imported metadata product subset produce `incomplete` findings. Root/XML errors are rejected. The subset uses literal exported property text; property-unit conversion and typed-value normalization are not supplied. Presence checks admit scalar values; exact-value checks require textual IFC Label/Text/Identifier values and mark measure/boolean/unit comparisons incomplete. A report's `pass` applies only to evaluated subset criteria, and every report declares `certification: false`. Neither XSD certification nor buildingSMART IDS/MVD/schema conformance is asserted.

Limits: 2 MB XML; 100 specifications; 20 facets per group; 200,000 checks; 20,000 detailed requirement findings. Exceeding a budget stops remaining specification evaluation with an incomplete finding. The UI displays up to 200 findings; exported reports retain the bounded report.

## Survey/CRS/breaklines/holes

`client/src/lib/surveyExchange.ts` supplies WGS84 EPSG:4326, spherical Web Mercator EPSG:3857, and WGS84 UTM EPSG:32601–32660 / 32701–32760 conversions. UTM uses a bounded ellipsoidal transverse-Mercator series, admits latitudes −80° to 84°, and limits forward longitude to within six degrees of the selected central meridian and the correct hemisphere. This is a limited analytic implementation rather than a datum grid/PROJ replacement. Web Mercator is unsuitable for precise survey measurements. Source/target CRS are explicit. LOCAL cannot be reprojected without georeferenced survey control. Vertical values and datums are never converted.

CSV rows are `easting,northing,elevation` with an optional header, up to 2000 points. LAS 1.1–1.4 uncompressed point formats 0–10 are read using header point offsets, scale/offset arrays and record lengths. Files are bounded to 64 MB and deterministically sampled to 2000 records. Classification is retained, but LAS CRS/VLR/WKT, waveforms, LAZ, feature-aware reduction and classification filtering are not interpreted. A surveyor must identify the CRS, vertical datum and metre elevations.

GeoTIFF support is classic II/MM TIFF, one north-up uncompressed strip band, 16/32-bit signed/unsigned integer or 32/64-bit floating elevation, `ModelPixelScale` and `ModelTiepoint`, inline EPSG GeoKeys, RasterPixelIsArea/Point and GDAL nodata. RasterPixelIsArea samples cell centres. File size is 64 MB and raster area at most 16 million cells; rectangular sampling retains at most 2000 valid cells. Compressed/tiled/rotated rasters, BigTIFF, multiple bands, alternate transformations and non-metre elevation units are rejected or unsupported.

The constrained TIN begins with the existing Delaunay survey triangulator and enforces breakline and hole-boundary edges by bounded convex edge flips. Constraint arrays contain zero-based existing point indices; holes are implicitly closed. Unique plan points are required. Intersecting/unsplit segments, nested holes or topology that cannot be enforced are rejected, not silently approximated. Hole interior triangles are removed after boundary enforcement. Constraints have at most 100 breaklines/100 holes, 1000 edges and a 15-million adjacency-operation limit. There is no exterior polygon clipping or survey accuracy certification.

Steepest adjacent-vertex drainage export follows downhill mesh edges to sinks. Pit filling, runoff accumulation, rainfall routing, travel time, culverts and hydraulic pipe/channel capacity remain separate engineering models.

## Civil alignment/earthworks

`client/src/lib/civilAlignment.ts` implements exact straight/circular plan coordinates, linearly changing curvature clothoid integration using composite Simpson quadrature, ordered continuous parabolic vertical curves, linearly interpolated superelevation and crowned cross sections when no superelevation is authored. Positive signed curvature/radius turns left; positive superelevation raises the left edge. Input is finite metre-based JSON, with an editable example provided in the workbench.

Terrain cross sections sample the constrained surface by barycentric interpolation. Road edges daylight into terrain with the authored horizontal:vertical side-slope ratio; edge crossings are refined by bisection. Missing terrain at sampled locations and sections that do not daylight within the maximum reach are marked incomplete. Cut/fill integrates sampled section differences, including sign crossings; volumes use average end areas only between consecutive complete sampled sections. The report includes quantified length so excluded intervals are visible. Narrow holes or survey gaps between sampled offsets or stations may remain undetected and their intervals can contribute approximate area/volume; the report explicitly warns about this. Refine intervals and independently verify full coverage before relying on quantities. These are study quantities rather than construction/certified BOQ. There is no pavement build-up, bulking, retaining-wall design, geotechnical design, highway standard compliance, spiral parameter fitting or superelevation design-code validation.

Limits: 100 segments/vertical curves/superelevation points; alignment length at most 1000 km; 500 reported stations; 50,000 terrain queries; 10,000 Simpson substeps per spiral position. Curvature discontinuities at segment joins are retained and reported. CSV and JSON exchange include the analytic alignment, sampled sections and limitations; no unsupported LandXML/native proprietary geometry is claimed.
