# Exact geometry chunk production

`geometryChunkProducer.ts` prepares exact whole-mesh partitions of an existing version-1 world-metre `GeometryScene`. It preserves every supplied position and index, triangle order, mesh id, sourceId, constant material, camera and warning. Meshes remain in input order and appear in exactly one chunk. Degenerate triangles and unused positions remain present. It creates no simplified geometry, transform, coordinate conversion, texture recovery, hierarchy or fabricated LOD. Each manifest chunk is a flat root with no children and `geometricErrorM = 0` because its stored geometry is an exact partition.

The input scene and its arrays are never overwritten or frozen. The producer owns a copied, frozen `sourceScene` and immutable canonical JSON `Blob`. The latter is a captured scene representation, not the original imported file's byte stream: whitespace, original key ordering and numeric spelling are not retained. Numeric negative zero is preserved in source/chunk JSON. Authored raw files and project/editor geometry remain the caller's originals and must be retained independently when needed. Existing source approximation/coverage warnings are copied rather than reinterpreted as verified geometry.

The producer rejects unknown scene/camera/mesh/material fields, unsupported prototypes/accessors, sparse numeric/mesh/warning arrays, blank identities, invalid values and excessive budgets. It requires explicit warning arrays of at most 100 strings/500 characters; it does not silently trim warning content. Both source and chunk geometry are validated through `inspectGeometryScene`: the camera is inspected once and every final chunk is inspected, with the union covering the captured source. Duplicate mesh ids are rejected globally; duplicate sourceIds are preserved because different mesh parts may refer to the same source object.

Prototype/unknown-field rejection applies to records. Required array entries are read as own data properties; array prototypes and extra non-index fields are not interpreted or retained. The captured sourceRevision is historical provenance, not a live server-revision check: binding reconciles the project ID and artifact metadata, while callers must recheck the project revision/generation before upload/application/save.

| Contract | Limit |
| --- | --- |
| Flat chunks | 14 |
| Source meshes | 4,096 |
| Total positions plus indices | 4,000,000 numeric entries |
| Source triangles | Existing 400,000-triangle scene limit |
| Canonical source JSON | 32,000,000 UTF-8 bytes |
| Source decoded reservation | 64 MiB |
| Each chunk JSON / decoded reservation | 8 MiB / 8 MiB |
| Bound provenance JSON | 2 MiB |
| Numeric work between event-loop yields | 4,096 entries |

Decoded reservations use 16 bytes per numeric entry, two bytes per identity/warning code unit, 2,048 bytes per mesh and additional scene/camera overhead. These are conservative accounting estimates, not measurements or a guaranteed browser heap ceiling. Caller input memory, browser/Blob implementation copies, hash buffers, UI/GPU allocations and garbage-collection timing also consume memory. Numeric serialization uses bounded UTF-8 pieces instead of a monolithic scene-sized string. Partition membership is checked with additive byte accounting before creating each chunk Blob. A single oversized mesh, too many chunks, or any other limit causes an error; no partial package or dropped geometry is returned. Whole meshes must be split upstream if necessary.

`produceGeometryChunks(scene, options?)` resolves to a runtime-frozen package containing `sourceScene`, source Blob/hash/size/counts/context, and chunks with ids, exact scenes, Blobs, hashes, bounds, reservations and mesh ids. Options are `signal`, `onProgress`, and a context `{ label, projectId, sourceRevision }`; project/revision are paired or both null. Chunk ids include both the deterministic captured source SHA-256 and the chunk SHA-256, so the existing cache cannot conflate different partition contents. `geometryChunkSourceMatches(package, currentScene, signal?)` can re-capture current scene data to reject stale work before commit.

`bindGeometryChunkArtifacts(package, projectId, { source, chunks: [{ chunkId, artifact }] }, signal?)` checks metadata returned by authenticated uploads: exact geometry kind, distinct 32-hex ids, SHA-256 and byte counts, complete chunk membership, and consistency with a captured project context. It returns an inspected, frozen manifest, bound provenance, immutable provenance Blob/hash/size, and source/chunk references. URLs use the existing authenticated same-origin project artifact routes. Hashes identify content and do not prove engineering validity or authorization; the server must still enforce project membership and artifact ownership.

Upload the bound provenance Blob, then call `geometryChunkWorkspaceReferences(boundPackage, provenanceArtifact)` to verify that artifact and obtain source + all chunks + provenance references. With 14 chunks this uses the full 16-reference limit. The workspace payload is a separate artifact, so a fresh maximum-size package plus snapshot needs 17 available project artifact slots. Existing server limits remain authoritative: 128 artifacts, 256 MiB total project storage, 64 MiB per artifact, and 16 distinct references per revision. The producer performs no upload, fetch, deletion, workspace save or capacity reservation. The caller must preflight actual remaining project capacity, preserve the original scene, manage upload rollback/conflicts, and retain protected references.

`AbortSignal` is checked before and after asynchronous work. Timer-task yields let UI abort events run during numeric capture and partitioning. Shared synchronous validators, `Object.freeze`, Blob operations and Web Crypto digest are bounded but cannot be preempted halfway through their native calls. Cancellation prevents package publication and later binding. The caller must abort on source mutation, project change or superseding jobs; changing values in mutable input arrays during cooperative capture is not an atomic snapshot. The immutable fingerprint describes the completed capture. A generation check and/or `geometryChunkSourceMatches` must precede applying or saving it. Fresh production/binding objects carry private runtime identity; JSON restored from a draft must be validated and regenerated from its retained source before reuse, not cast to these objects.

Platform references: [W3C Web Crypto Recommendation, digest](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/#SubtleCrypto-method-digest), [WHATWG DOM AbortSignal](https://dom.spec.whatwg.org/#interface-AbortSignal), and [WHATWG HTML timer tasks](https://html.spec.whatwg.org/multipage/timers-and-user-prompts.html#timers). Geometry/workspace limits were inspected in the repository's `meshGeometry.ts`, `geometryPipeline.ts`, `workspaceApi.ts`, `ProjectWorkspacePanel.tsx`, and server workspace contracts.

Verification for this library increment is source inspection only. Repository code, numerical examples, tests, builds, typechecking, linting, native tools and previews were not executed. Browser cancellation responsiveness, hashing/serialization performance, cache/GPU behavior and exact peak memory remain unverified. UI/server production integration remains separate next work; a library implementation does not complete Phase 6.

Independent source review found no blocking contract/type issue in the inspected partition/binding paths and clarified array-field and historical-revision limits above. This inspection does not verify compiler or runtime behavior.
