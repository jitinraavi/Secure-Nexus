# Engineering declarations in CAD and BIM exchange

`exchangeProvenance.ts` copies a normalized project engineering basis into an explicit unverified declaration. Country, region, authority, adopted editions/amendments, reviewer, site/material/load declarations and supplied criteria remain available with the exchange. A confirmed declaration is not code compliance or accepted analysis. Missing legacy basis is recorded as null with a declaration issue, rather than inventing an adoption.

The IFC-like coordination JSON includes `engineeringProvenance`. IFC4 STEP writes a custom **SecureNexus Engineering Basis** property set on the project with the complete JSON declaration and readable country/compliance/verification properties. Its declaration payload uses bounded ASCII JSON escapes so Unicode metadata survives JSON recovery without introducing raw Unicode into the STEP property text. Imported declarations reject unknown captured basis/declaration/standard/criterion fields and sparse arrays before normalization. This is application provenance, not a standard buildingSMART property set or certification. The existing geometry approximations remain visible.

Version-1 imports retain bounded, dense captured issue strings verbatim (at most 1024 records of 2000 characters; the combined imported list also stays within 1024 records). Catalog or review-rule updates do not invalidate a historical declaration solely because its captured findings differ: current findings absent from the captured list are appended as `Current review:` notices. An empty captured list does not establish current adoption acceptance. The captured basis remains unverified. IFC import shows up to ten findings and retains the complete combined list in its metadata export. Structural conversion summaries reserve at most 100 warning records for captured/current declaration findings, including an explicit omitted-count notice when needed; retain the original exchange for the complete captured declaration and review the current basis separately. Optional IFC readable labels may be omitted; every present recognized label must be a single IFC label property agreeing with the captured declaration, including rejecting duplicate or unsupported property types. Repeated engineering property assignments, unresolved references and property lists above 1024 records are rejected before another declaration payload is parsed.

R2000 DXF writes numbered group 999 comment chunks with ASCII-escaped JSON. Concatenating the chunk payloads in their numeric order reconstructs the declaration. Autodesk documents that comments are ignored on open and may be omitted on save; converters may discard them too. Use the separate declaration JSON for durable downstream provenance. No preservation through DWG conversion is asserted.

The shared export menu offers the exact declaration JSON. The main editor's coordination ZIP includes it beside IFC/DXF/OBJ artifacts. PDF sheet sets append a human-readable declaration, adopted references and criteria, with the existing pagination and size limits. The PDF's ASCII font substitutes other characters; the JSON retains the exact original text.

Community structural solver exchanges accept the top-level basis as an optional argument and include the same provenance. The 2D/3D geometry bridges validate that optional metadata while preserving compatibility with old exchanges. Workbench structural-file imports copy the validated captured basis; MEP design-file imports copy the design's explicit basis. Legacy files without a declaration create an undeclared analytical basis with a visible warning, preventing a previous workspace's adoption from being attributed to newly imported geometry. All conversion/metadata checks complete before state is replaced. Imported metadata does not certify supports, loads, member properties or external results. An independently edited analytical draft must retain its own reviewed basis.

Primary format references: [IFC4 property assignment](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifckernel/lexical/ifcreldefinesbyproperties.htm), [Autodesk DXF group 999 comments](https://help.autodesk.com/cloudhelp/2024/ENU/AutoCAD-DXF/files/GUID-3F0380A5-1C15-464D-BC66-2C5F094BCFB9.htm). No app, compiler, build, test, converter, PDF renderer or format validator was executed. Compiler/interoperability acceptance and comment preservation remain unverified.
