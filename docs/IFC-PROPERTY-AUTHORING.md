# Existing IFC occurrence property authoring

`client/src/lib/ifcPropertyAuthoring.ts` exposes `parseIfcPropertyEdits(unknown)` and `exportIfcPropertyEdits(document, edits)`. The request is `{ "version": 1, "edits": [...] }`, containing at most 100 records with exactly `productGlobalId`, `propertySet`, `name`, `dataType` and `value`. Empty lists leave source unchanged. Duplicate targets, unsupported fields, sparse arrays and malformed scalar values reject the whole request before a result is returned.

The six supported data types are IFCLABEL, IFCTEXT, IFCIDENTIFIER, IFCBOOLEAN, IFCINTEGER and IFCREAL. JSON values must match their primitive type. Label/identifier values contain at most 255 UTF-16 code units; text contains at most 2000. Printable BMP Unicode uses STEP X2 encoding; supplementary characters use one X4 code point rather than isolated surrogate blocks. Quotes and backslashes are escaped. Unpaired surrogates and control characters are rejected. Integers are safe integers; reals are finite with magnitude at most 1e100 and use an explicit STEP real token. Boolean values use unquoted .T./.F. tokens. No add/delete, unset-to-value, type change or physical-measure/unit conversion is supplied.

Nonempty requests reimport the bounded supplied source before ownership checks: mutable supplied entity/property caches cannot authorize an edit. Each target must identify one unique source product GlobalId and one supported direct occurrence property. Product metadata ambiguity or unsupported metadata prevents authoring. Inherited values cannot be edited; a valid direct occurrence value may coexist with other inherited properties, but no type property is mutated. The property and its set must each have exactly one incoming reference across all parsed STEP entity arguments. The set must have one direct property relationship whose related-object list contains exactly the selected product. Shared sets/properties, additional constraint/dependency references, repeated relationships, unresolved references and multiple-product relationships are conservatively rejected. These are application limits; IFC itself permits property reuse.

The exporter locates only the existing property's third argument (NominalValue) in its original source range, respecting quoted strings, doubled quotes, nested values and comments. Descending, non-overlapping patches retain every byte outside that token, including surrounding comments/whitespace, property names/descriptions/units, all GlobalIds, geometry and unsupported records. Unchanged values produce no patch. All edits validate before a source result is returned; the imported document is never mutated. Callers must reimport the returned source before subsequent authoring, metadata export or IDS checks, clear prior reports, and preserve the original uploaded file as a separate artifact.

Existing source bounds remain 20 MB, 100,000 entities, one million reference-scan values and depth 32. Reference counts and direct assignments are indexed in one entity walk. Nonempty authoring incurs an additional bounded source/geometry parse, and callers reimport the edited result; no performance measurement is claimed. No broad schema conformance, proprietary parametric round trip or authoring certification is claimed.

Primary inspected references: buildingSMART IFC4 ADD2 TC1 [IfcPropertySingleValue](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifcpropertyresource/lexical/ifcpropertysinglevalue.htm) defines nominal values, optional units and reuse through property sets/complex properties/dependencies; [IfcLabel](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifcmeasureresource/lexical/ifclabel.htm) and [IfcIdentifier](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifcmeasureresource/lexical/ifcidentifier.htm) constrain their strings to 255 characters; [IfcBoolean](https://standards.buildingsmart.org/IFC/RELEASE/IFC4/ADD2_TC1/HTML/schema/ifcmeasureresource/lexical/ifcboolean.htm) distinguishes Boolean from textual values. UTF-16 bounds and exclusive-reference rules are conservative product limits.

Source inspection and primary-document reading only. No app, compiler, test, build, lint/typecheck, preview, sample edit or IFC validator was executed. Later acceptance must exercise string/comment token ranges, Unicode and scalar spelling, shared references, exact-pair metadata identity, duplicate GlobalIds, inherited/ambiguous/unitful rejection, unchanged-source preservation, reimported edited metadata/IDS and saved workspace recovery.
